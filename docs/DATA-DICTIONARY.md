# 定义表 ledgerbank

## 数值

- 金额、手续费一律 `Decimal`，量化为 0.01 元，对外输出十进制字符串。
- 禁止 float 累加；合计由同一套 `Decimal` 路径复算。
- 银行侧签向金额 = 金额 × 方向（收 +1，付 −1）；签向手续费固定为负向支出。
- 大整数编号（如 9007199254740993）全程按字符串保存，不过 `int()`。

## 时间

- 存储与比较一律 UTC，页面按 +08:00 展示。
- 带偏移时间按其偏移换算；纯日期按 +08:00 当日 00:00 换算。
- 本地日桶是半开区间 `[日初, 次日初)`；候选日期差按本地日相差的自然日数计算。

## 键与去重

- 银行侧业务键：流水号；账簿侧业务键：凭证号。
- 同一业务键出现多条有效行：保留发生时间最早的一条，时间相同取文件行号小者，其余进隔离区。
- 业务键只用于去重与组内引用，不用金额或名称生成。同一天、同额、同摘要但流水号不同的两笔流水
  是两笔真实交易，各自保留，不合并、不去重。
- 没有流水号的隔离行（缺字段、日期错、账户未登记）按「来源文件 + 行号」定位，不参与业务键去重。

## 补传合并

同一侧可以分批补传多份文件，两份文件的日期范围允许重叠。导入时逐账户判定形态：

| 判定 | 条件（同一账户） | 结果 |
|---|---|---|
| 首份基准 `initial` | 旧集合里没有该账户 | 直接作为基准 |
| 整段重出 `replace` | 新文件日期段内的旧流水号全部出现在新文件里；或新文件完整包住旧区间且重述覆盖 ≥ 80% | 同流水号以新文件为准；旧文件在该段内独有的流水视为撤回 |
| 只补新增 `cumulative` | 与旧集合没有共同流水号，或只重述了少数旧行 | 新流水追加，旧文件独有流水保留 |
| 混合 `mixed` | 部分账户重出、其余账户累计 | 按账户各自处理 |
| 未生效 `noop` | 空文件、仅表头、全空行 | 不写入，保留该侧旧版 |

- 撤回只作用于「本次文件正在重述的来源文件」：一份与本次文件毫无交集的独立补传（晚到扣款），
  即使在日期段内也保留。每条流水带 `origin_sha` 记录最初来源，替换不会改写它。
- 末行截断或大面积列数不齐的补传视为坏导出，自动判定时强制按累计处理，绝不用它撤回旧行；
  显式指定 `mode=replace` 时以用户选择为准。
- 生效顺序按导入序号 `source_seq`：旧来源比本次更新时，重叠流水号保留旧来源；同一文件重跑复用原序号。
- `run_id` 由两侧「合并后有效集合」的内容摘要计算，同一批交易无论由一份全量文件还是「基准 + 多次补传」
  得到，都落进同一批次；页面、接口与下载文件都读取同一批有效交易。
- 导入在解析、合并或落库阶段失败时整体不写入，旧批次完整保留。

## 空值

- `null`、空串、`-`、`--`、`N/A`、`NA`、`NULL`、`NONE`、`未知` 是空值哨兵，只在一处定义。
- 金额为空值 → 隔离，原因码 `AMOUNT_SENTINEL`；手续费为空值 → 按 0 计。
- 空文件、仅表头、全空行是三种空态，分别返回 `EMPTY_FILE`、`HEADER_ONLY`、`ALL_BLANK`。

## 匹配与手续费

- 容差 0.02 元，窗口 3 天，子集上限 4 条；三者进入 run_id 的计算参数。
- 匹配金额只用金额与方向，不用手续费；手续费单独汇总在银行侧。
- 组内手续费分摊权重 = 组内银行签向金额绝对值，尾差按最大余额法分配，分摊合计必须等于组内实际手续费合计。
- 匹配差额 = 银行匹配金额 − 账簿匹配金额，容差内允许非 0。

## 状态

- 行状态：`valid`（参与对账）、`quarantine`（隔离，附原因码）。
- 批次状态：`partial_bank`、`partial_ledger`、`ready`、`matched`。
- 原因码表在 `app/reasons.py`，页面、CSV 与清单共用同一份名称。
- 补传形态：`initial`、`replace`、`cumulative`、`mixed`、`noop`，随运行清单的 `inputs.<side>.merge` 保存。

## 运行清单

- `run_id` 由规则版本、两侧「合并后有效集合」的内容摘要、参数共同计算，同一批交易重跑得到同一 `run_id`。
- 清单包含输入文件名、文件 sha256、有效集合摘要 `effective_sha256`、字节数、规则版本、参数、计数与耗时。
- `inputs.<side>.sources` 按导入序号列出该侧所有补传文件，标出 `active`（是否仍在有效集合中）与
  `rows_in_set`（贡献的行数），据此可追溯每条有效流水来自哪一份文件。
